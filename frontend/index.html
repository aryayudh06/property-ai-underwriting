Structured Data Extraction

Gunakan LLM (Ollama, via LLM Extraction Service) untuk membaca teks hasil OCR dokumen dan mengisi form data underwriting secara otomatis. Semua field tetap dapat diperiksa & diedit.

🔍 Search Riwayat Klaim (Database SQLite Dummy)

Mencari riwayat klaim atas nama Tertanggung pada case ini di database klaim internal (tabel claim_history, data dummy). Murni query database - tidak menggunakan LLM.

Klik "Cari Riwayat Klaim PT" untuk memulai pencarian.

📚 RAG Knowledge Base

Upload & indeks pedoman underwriting, SOP, risk appetite, manual risiko, ketentuan produk, dan template disposisi. Dokumen diindeks menjadi vektor embedding (lokal, offline) dan disimpan di SQLite sebagai vector database sederhana; pencarian memakai cosine similarity (retrieval only - LLM tidak membuat aturan tanpa sumber dari sini).

"Retrieval saja" hanya menampilkan potongan dokumen paling relevan (tanpa LLM). "Retrieval + Jawaban Gemini" menyuntikkan potongan tersebut ke Gemini (context injection) untuk disusun menjadi jawaban naratif - digrounding ketat pada potongan yang ditemukan; jika Gemini belum dikonfigurasi (GEMINI_API_KEY), sistem otomatis memakai mode mock (ekstraktif) sebagai fallback.

📝 Disposisi Underwriting

Disposisi disusun otomatis dari Informasi Risiko, hasil Search Riwayat Klaim, dan Subject To/Conditions Rule Engine (berbasis konfigurasi & data, dilengkapi rujukan Knowledge Base) - teks akhir tetap dapat diedit bebas oleh underwriter sebelum difinalisasi.

Input Informasi Placement & Rekomendasi (opsional, isi sebelum Generate)

🧭 Analisis Kualitatif

Merangkum seluruh hasil Disposisi Underwriting versi terbaru (Informasi Risiko, Riwayat Klaim, Subject To/Conditions, Rekomendasi, Koordinasi Cabang), digabung dengan Analisis Risiko Bencana Wilayah atas Lokasi Risiko case ini (pemantauan berita publik terkini via Google News RSS - murni web scraping + keyword heuristic, bukan LLM). Jalankan Generate Disposisi di atas terlebih dahulu.
